# 大章节切分方案 · 实施计划（重写版）

> 状态：**方案已对齐，待落地**。既往「离屏断点测量器 / 屏断点」思路作废，重写为「段落切分 + 可变窗口」。
> 背景关联：[`ARCHITECTURE.md`](ARCHITECTURE.md) §8 分页模型重构。

---

## 0. 一页总结

```
整章排版一次碎片化 → 卡死（根因）            [现状：paginator.js columnize/expand 一次排整章]

大章按段落拆成若干「段落段」，每段 ≈ 3~8 屏（10 屏为不卡上限）
   → foliate 三窗口只渲染当前±1 段
   → 单次排版量 = 一个段（几屏），而非整章 → 打开/翻页不卡
   → 屏幕滑动窗口在段内滑到「刚好分屏」位置
```

屏幕相对已排段 = **滑动窗口**；`scrollLeft` 控制看到段的哪一部分。切分的目的不是"按屏精确断"，而是**阻断"一次排整章"**——段内仍由 foliate 多栏细分。

---

## 1. 根因（已通过源码确认）

foliate 分页模型 = 「一章 = 一个 section = 一个 View，用 CSS columns 一次碎片化整章」。

| 机制 | 源码位置 | 结论 |
|---|---|---|
| 整章一次 `columnize()`（`column-width=size` 切列） | `paginator.js` L319-365 | 一次排整章 |
| `expand()` 把文档撑到 `pageCount×size` 宽（全列 layout） | `paginator.js` L387-444 | 整章全部 layout、占内存 |
| 三窗口 `#shiftWindow` 维持 ±1 共 3 个 section | `paginator.js` L860-890 | 只限"章数"，不限章内列数 |

**结论**：卡顿/内存的根子＝整章铺进单 section、整章全量 columns。三窗口机制正确，问题全在**单 section 内列数不可控**。切分方向＝把单 section 内容量压到「一次排版不卡」的量级（≈3-8 屏 / 10 屏内）。

---

## 2. 关键认知（推翻旧思路的两点）

1. **WebView 无真后台 DOM 排版。** Worker 无 DOM；「离屏 iframe 后台排整章」本质仍占主线程，等于把"整章排版卡"移到后台，只是把白屏改成"先加载中再等"，**没治本**。→ 弃用「离屏断点测量器」。
2. **不按"屏"切，按"块"切。** CSS 列排版能把段内多栏细分到屏；精确"分屏点"不需要预测——**屏幕滑动窗口滑到分屏线即可**。切分只负责"把大章拆成若干不卡的段"，分屏由 foliate 多栏 + 滑动窗口共同完成。

---

## 3. 切分粒度

- **段目标**：≈ 3~8 屏内容量，**10 屏为不卡上限**（现代 CPU 单次排版 10 屏量级不卡）。
- **宁可偏小，不超过上限**：多拆一段（切换频繁）可接受，超过上限（卡死）不可接受。
- **小章节不拆**：整章本就不卡 → 直接交给 foliate。
- **字节只做第一道粗筛**：字节数估算「要不要拆 + 拆几段」，不精确决定段界（字节≠屏数，含图/代码块/表误差大）。

---

## 4. 切分规则（三层，断点恒在块顶端）

```
① 顶层块切：按 body 直接子元素（p/div/...）顺序累计内容量，达段预算时
   在「某一块的顶端」切断 → 断点是块边界，绝不在文字行中间
② 独大向下递归：某块（如一个大 div）独大超预算 → 进入其内部，
   在它内部子块顶端切（仍块边界）
③ 不可分超大块 > 一整页（超大 <pre> / MathML / 大图）→ 整块放行不切，
   靠 foliate 多栏 `break-inside:avoid` 整块换列
```

**容器克隆（全链路）**：断点在深层时，把 `root → 断点` 的整条祖先链（body/section/div/...）**克隆成多套**，每套继承该链路上的容器属性（保样式），各承一个分支。

```
<body><div class=box><p>…</p></div></body>  断点在 box 内
  → <div class=box>[段1]</div>
    <div class=box>[段2]</div>            // box 克隆成多份，样式不丢
```

原因：样式可能挂在任一祖先容器上，只克隆命中层会丢祖先样式。

## 5. 首屏与窗口渲染

- **打开书**：按上次阅读位置（章 index + 字符锚点）定位 → 优先排版「该位置所在段」及其相邻 ±1 段 → 首屏显示在阅读位置。
- **三窗口**：若小章整章；若大章切段后，foliate 三窗口自然只驻留「当前 ±1 段」，其余段销毁。
- **平时只排一个窗口**：当前段已加载，翻到相邻段多为命中或低开销冷排；只有切到未排过的新段才排那一个段。

## 6. 分步实施（每步含验收）

### Step 1 · 段落切片器（重写 split.js）
- 按 §4 规则把大章 DOM 切成若干段；每段生成独立文档片段（继承 `<head>` 资源 + 全链路容器克隆）。
- `load()` 返回完整 HTML 文档字符串（foliate 用 `sections[index].load()` 拿整章字符串）。
- 小章不拆；每段 3-8 屏内容量。
- **验收**：打开 GIMP 手册大章，日志显示拆成 N 段，段边界在块顶端、容器样式保留。

### Step 2 · 注入 book.sections（修白屏根因）
- 旧实现在打开前对全书遍历拆分 → 同步解析所有章 HTML → **卡死白屏**（已定位）。
- 修正：**只拆分当前读到的章（或按需懒拆）**，不在打开时拆全书；拆分当前章也要注意别阻塞首屏（先渲染首段，其余后台/按需拆）。
- **验收**：打开大章不再白屏；翻页不卡。

### Step 3 · 段内分屏体验
- 确认段内多栏细分 + 滑动窗口滑到分屏线；段边界吸附正常（衔接上一段末尾 → 下一段开头）。
- **验收**：跨段翻页顺滑、无空白屏、无两段之间停留。

### Step 4 · 下标偏移重映射（★过期必做，勿遗漏）
> **关键隐患（本处固定记录）**：拆分会把大章在 `sections` 数组中从一个下标展开成多个连续下标 → 该章**之后**所有章名的下标整体后移 → 依赖 index 的进度 / 书签 CFI / 上(下)章翻页边界全部跟着偏。
> POC 阶段（Step1-3）**明确暂不处理**，只验证「调入窗口时懒拆 → 分段排版 → 翻页不卡」。以下为 Step4 恢复清单：
- 「原章全局字符偏移 ↔ 段 index + 段内偏移」互转；进度重算（`sizeTotal` 不变）。
- section 展开后，**该章之后所有章节下标偏移**须重映射（一次性建全局偏移表）。
- CFI/书签/重开定位/进度 seek 连续正确。
- **验收**：重开、seek、书签都定位到同一段文字；整书进度连续不跳变。

### Step 5 · 改设置重切
- 字号/行距/边距/旋转改变 → 读当前字符锚点 → 重切当前章 → `goTo` 恢复（锚点行保持在当前页靠上）。
- **验收**：改字号后停在原文字处，基点不漂移。

### Step 6 · 缓存与回归
- 段拆分结果按「书 + 排版参数」缓存；回归目录、章标题、`snap` 双翻修复、书签。

## 7. 待用户确认的取舍

1. **切分粒度**：3-8 屏 / 10 屏上限（已确认）。若用户觉得切换频繁，可在设置里暴露粒度旋钮（把"卡不卡"判断交给用户）。
2. **懒拆策略**：打开只拆当前章 + 按需懒拆，不再打开时拆全书（已确认，修白屏）。
3. **向前懒加载**：定位处向后懒切没问题；**向回翻**到未切段时需重排该段——接受"回翻到常不看处偶尔卡一下"，详见 ARCHITECTURE §8 已记录的返回重排代价。
