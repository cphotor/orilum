## 1. 背景与动机

### 1.1 旧路线的缺陷（为何推翻）

当前实现以 foliate-js 的 `Paginator` 为核心：为「无缝跨章」把前/中/后三章拼成一条连续长条，靠 `#offsets`（各章绝对偏移）+ 滚动补偿（`containerPosition += diff`）维持衔接。由此产生三个结构性冲突：

1. **offsets 与 scrollLeft 天然不同步**：每次窗口增删，`#layoutViews` 从窗口首章重算所有章偏移；`scrollLeft` 是独立变量，只能靠补偿找齐——补偿时机稍错（动画中/刚落位/被浏览器 clamp）就乱跳。
2. **章节宽度是异步的**：预读章字体加载完成前宽度是兜底值，`expand` 后变真实值 → 再次重排 → 再漂移。
3. **多个回调各自为政**：`loadView` 后补偿、`afterScroll` 延迟迁移、`render` 重排，都在不同时机动 `scrollLeft`/offsets，互踩。

结论：**补丁只能压制现象，不能根除**。跨章乱跳、大半屏弹回、连翻两页均源于此。

### 1.2 新路线的基本判断

- 排版能力（HTML → 横向长条、页定位、CFI）是 foliate.js 的价值，**保留并缩小其职责到「单章排版 + 页定位」**。
- 滚动翻页、跨章、动画不是它的能力（只有 scrollLeft 线性插值），**且未来需要的卷页动画它完全做不了** → 动画层自研，用真实 DOM + 3D 变换。
- 「翻页动画需要前后两屏内容衔接」是唯一需要多章内容同时存在的地方 → 用**独立的章节长条 + 切换**解决，不拼接。
- WebView 排版结果（DOM 长条）**无法序列化落盘**；能持久化的是「平铺资源（HTML/图/CSS）」与「屏幕位图」。

## 2. 角色分工（写死）

| 模块 | 职责 | 不做什么 |
|---|---|---|
| foliate.js | 单章排版：喂 HTML + 样式 → 产出横向长条（真实 DOM）；页定位；CFI/选区 | **不再**负责多章拼接、滚动翻页、窗口迁移、滚动补偿、任何动画 |
| 自研 · 视图层 | 章节长条的挂载/切换；当前章是唯一可滚动视图 | — |
| 自研 · 动画层 | 章内翻页动画、跨章过渡、未来卷页（真实 DOM 3D 变换） | — |
| 自研 · 调度层 | 章节预排优先级调度；章节全驻留缓存 | — |
| 自研 · 图片策略 | 按需采样解码、离屏懒加载 | — |
| 自研 · 恢复层 | 跨会话三屏位图持久化、重开秒显、无缝恢复 | — |

## 3. 章节长条模型（数据基础）

```
章节资源(HTML) ──► foliate.js 排版 ──► 一条横向长条
                                     · iframe 内 CSS columns 多列
                                     · 宽 = 章页数 × 屏宽（页 = 屏宽步长）
                                     · 滚动定位 = 页 ↔ scrollLeft
```

- **一页 = 长条上一步（屏宽）**；一章 = 一条独立的、完整的、可滚动的长条。
- 章内翻页 = 在当前章长条内滚动（单条 scrollLeft，**无拼接、无 offsets 重排**）。
- 每章长条一旦排好，**常驻不丢**（见 §4）。

## 4. 章节驻留与预排调度

### 4.1 全驻留（不淘汰）

- **已排版章节长条全部保留，永不丢弃**。资源评估显示非瓶颈：
  - 纯文字书全书 ≈ 80–150 MB；计算机书（含插图）≈ 250–700 MB（大头是图片解码）。
  - 现代平板可用内存 2GB+，数十章驻留无压力。
- 因此不作 LRU 淘汰；只保留“容量上限”作为理论兜底（可设 20–30 章，日常碰不到）。

### 4.2 预排调度（优先级）

目标：**运行时至少「前章 + 当前章 + 后章」三个独立长条就绪**（三窗口，但互不拼接、各自独立）。

- **第一优先**：当前章（打开书立即排版渲染）。
- **第二优先（按当前位置）**：
  - 当前页靠章首 → 优先排前一章；
  - 当前页靠章尾 → 优先排下一章。
- **边界特例**：打开书直接定位到书中部、且正好在章开头 → 前一章可能未排完，此时**优先补排前一章**（回翻是高频操作）。
  - 回翻只需前一章**最后一页**：即便该章很大，也只取末尾那屏，开销小。
  - 前翻遇下一章是大章（如 GIMP 手册级）→ 见 §7 大章预案。

### 4.3 调度触发

- 每次翻页 / relocate 时评估当前页在章内位置，节流触发邻章预排。
- 预排是后台任务，不阻塞当前章翻页。

## 5. 翻页与跨章动画（自研，与引擎解耦）

- **章内翻页**：当前章长条内滚动动画（真实 DOM，自写动画代码）。
- **跨章**（当前章末屏 → 下一章首屏）：
  1. 动画层准备两张画面：当前屏、目标屏（均来自真实 DOM 或位图快照）；
  2. 位图/3D 过渡动画（滑动、淡入等，自研）；
  3. 动画完成瞬间：**把相邻章长条设为当前视图**，定位到对应页，隐藏过渡层。
- 前置依赖：**目标章长条已就绪**（§4.2 预排保证相邻章就绪）。截图准备时机提前于动画启动，是跨章质量的关键。
- **未来的卷页动画**：同一套“真实 DOM 3D 变换”架构上新增变形模式即可，不推翻结构。

---

## 6. 跨会话恢复（三屏位图）

> 目的：重新打开书立即可用，节省排版等待。

- 退出时：把「当前屏 + 前 1 屏 + 后 1 屏」渲染成**三张位图**，持久化到磁盘。
- 重新打开书：
  1. **秒级显示**三张位图（用户立即看到上次阅读位置的画面，零等待排页）；
  2. 后台并行恢复：章节资源（本地缓存）→ 重建长条 → 排版 → 定位到上次页；
  3. 恢复完成 → 位图**无缝过渡**到真实 DOM 内容。
- **失效策略**：字号/字体/边距等排版设置变更后，旧位图与真实排版不符 → 删除位图，重开走正常加载。

> 说明：位图只负责「重开瞬间」；阅读过程中的翻页/跨章动画截图是另一套（运行时实时生成），两者用途不同。

## 7. 大章预案

- **章节体积预检**：排版前先获知章节体量（HTML 字节/词数，可快速预读，无需完整排版）。
- 小章/中章 → 按 §4.2 预排，跨章无缝。
- 超大章（排版耗时超过可用提前量）→ 无法在滑动期间排完：
  - 显示「下一章排版中」过渡屏（或前一章末屏重影/纯色占位）；
  - 排版完成后用目标屏位图淡入；
  - 资源侧：回翻只需上一章**最后一页**，即使大章开销也小。

---

## 8. 与现有代码的关系与迁移

- 现有 `paginator.js` 中的多 View 拼接 / offsets / 滚动补偿链路**废弃**，不再作为翻页主路径。
- 保留可复用能力：单章排版（`View.load`/`columnize`/`expand`）、页定位、CFI、样式注入、平行资源加载。
- 迁移路径：以章节长条驻留模型重写视图/调度/动画层，先修「章内翻页 + 跨章切换」稳定，再做卷页。

## 9. 决策录

**已拍板：**
- foliate.js 职责收缩为「单章排版 + 页定位」，动画/视图/调度/缓存全部自研（§2）。
- 章节长条全驻留、不淘汰；图片按需采样解码（§4）。
- 三窗口 = 三个独立长条（不拼接），运行时就绪；按当前位置决定邻章预排优先级（§4.2）。
- 跨章动画 = 动画层位图/3D 过渡 + 落位切换章节视图（§5）。
- 跨会话恢复 = 三屏位图持久化 + 重开秒显 + 后台恢复无缝过渡（§6）。
- 动画方向 = 真实 DOM + 3D 变换（拒绝位图化导致的失真），为卷页预留（§5）。

**待细化（实现阶段）：**
- 预排调度触发的节流窗口、就绪判定、内存压力时的降级细节。
- 大章过渡屏的具体形态与视觉。
- 三屏位图的存储格式与恢复时序细节。
