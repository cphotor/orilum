## 1. 架构总览（分层）

```
┌──────────────────────────────────────────────────────┐
│ Kotlin 薄壳层（Application / Activity / ViewModel）      │
│  · 书架 · 进度/书签/笔记 UI · 阅读 overlay · 原生 pager   │
├──────────────────────────────────────────────────────┤
│ Kotlin 数据层（自建）                                    │
│  · 解析器：解 zip → 读 container.xml → opf/spine/目录     │
│  · 定位：章节 + 字符偏移 / CFI 兼容                       │
│  · 持久层：进度 / 书签 / 笔记 / 修订（Room）               │
│  · 字体：样式体系（主题 + 逐条 + UI 控件）分层             │
├──────────────────────────────────────────────────────┤
│ 通信桥（JSBridge）                                      │
│  · Kotlin ⇄ WebView（JS）：派发章节、上报进度、注入样式      │
├──────────────────────────────────────────────────────┤
│ WebView + foliate-js（渲染层）                          │
│  · 排版 / 按屏切页 / 文本与选区 / CFI / transformTarget    │
│  · flow=paginated | flow=scrolled（两种浏览模式原生）      │
└──────────────────────────────────────────────────────┘
```

**职责边界**
- **foliate-js 只做**：排版输出、把内容按屏切成页、给文本/选区/CFI、加载章节资源。
- **Kotlin 全权负责**：解析、定位、进度/书签/笔记、翻页容器与动画、字体与样式分层、科技渲染钩子。
- 遵循“JS 只负责排版、其他尽量自己来”的既定方向。

## 2. 渲染管线与页面化（动画的地基）

关键：**割离「排版」与「翻页呈现」**，让动画成为原生层的独立能力。

1. foliate-js 在 `flow=paginated` 下按视口把某章切成若干页（每页一个 viewport）。
2. **页面化**：Kotlin 把当前可见页渲染成位图（`captureIntoBitmap` / 截屏），或按页独立视图持有。
3. **原生 pager**：在页位图之间切换，负责动画与手势，Kotlin 持有。
4. 进下一页 → 请求 foliate 下一页范围 → 渲染新位图 → 预加载下一张。

> 这样第一阶段只要“滑动翻页”就用原生 pager 的滑入滑出；卷页作为**同一 pager 上的动画插件**单独加，不影响架构。

**页面化代价（需在工程中接受并控制）**
- 位图内存：需要按页回收 + LRU；大图/长字重注意。
- 文本选中、链接跳转、放大：位图页不原生可交互，需按需“热切换”回真实 DOM 页。
- 方案取舍：滑动翻页既可“位图 pager”，也可“每页一个轻量 WebView 页”。首版建议**位图 pager + 单 WebView**，稳定后再评估。

## 3. 两种浏览模式（原生）

| 模式 | foliate-js `flow` | 交互 |
|---|---|---|
| 翻页式（单栏整页） | `paginated` | 竖屏一屏一页、左右翻页；原生 pager 动画 |
| 滚动式（全书连续） | `scrolled` | 纵向连续滚动；章节间无缝衔接 |

- 切换 = 改 `flow` 属性，运行时切换，无需重建。
- 两种模式均**原生一级公民**，这正是换引用的关键收益。

- 解 zip（标准 zip 库）→ `META-INF/container.xml` → `package.opf` → `spine` / `manifest` / `toc(nav)`。

## 6. 字体与排版（样式体系）

### 6.1 载体与分层

> 早期方案（五分类 + L1/L2/L3 + 中英分离）已被**样式系统**（主题列表 + 逐条输入 + UI 常驻控件）整体取代。

- foliate-js 提供 `fontSize/fontFamily/settings` 等原生项；但**多分类字体与“跟随原书”/替换字体** 是差异点，需自写。
- 实现载体：foliate-js 的 `transformTarget` 事件钩子（渲染前改写 DOM）+ 注入自定义 CSS 层（`reader.html` 的 `buildReadingCSS`）。
- 新样式体系分层：UI 界面常驻控件（最高优先，随时可调）→ 逐条输入 → css 主题模板（现代/传统/模板）→ 原书设置（“不覆盖”层）。
- 中式字重：粗→黑体、斜→楷体（非合成样式）等，按原设计实现。

### 6.2 样式系统设计（复杂度按场景分级）

三场景对应三档设置密度，**互斥入口**，而非一套机制通吃所有书：

| 场景 | 意图 | 入口方式 |
|---|---|---|
| 1. 原书设置 | 书内 CSS 生效，字体靠内置三款兜底（衬线/非衬线/等宽），缺字体才替换 | 「原书设置」作为一个主题选项 |
| 2. App 统一呈现 | 忽略书内 CSS，App 默认排版，零配置 | 排版主题列表单选 |
| 3. 用户指定样式 | 主动改版式者进入，设置极致简洁 | 列表管理 + 逐条输入 |

三场景统一用「列表选择」表达——**原书设置也作为一个主题选项**，不用开关，全部走列表单选。

#### 三层样式控制 + 背景

- **原书设置**：App 内置衬线、非衬线、等宽三种替换字体，做缺字体兜底。
- **排版主题**（列表单选）：
  - 现代模式：无首行缩进，段落靠段间距区隔。
  - 传统模式：首行缩进两字符，无段间距。正文采用衬线字体。
  - 原书设置：不注入排版规则，仅缺字体兜底。
  - 预留模板扩展位（段首放大等），后期由模板 css / 用户自定义 css 补充。
- **用户自定**（列表管理）：
  - **替换字体**（次高优先）：逐个字体选择替换字体。
  - **手写选择器**（最高优先）：左右两个列表框（选择器 h1/p/code/strong/em… × 属性 line-height/font-family…）+ 输入框填样式值，逐条追加成列表、可单行删除，后者覆盖前者。

#### 字号体系（相对默认缩放）

- **根锚=正文**：UI 字号滑块设正文字号（根 em），全书字号 = 正文 × 各元素自身 em 比例，根一变化 → 整体等比缩放、不打架。
- **默认比例表**：如 h1≈1.5em、h2≈1.3、p=1em、code≈0.9…（可微调）。
- **“单独改某元素尺寸” = 改该元素的 em 比例值**，不存固定 px。
- **UI 字号滑块以正文 px 为步进**（9–36px，0.1px 步进），拖动换算存盘为 `fontScale` 档位（刻度 0.5..2.0，50 = 各元素自身默认 1.0）。相对默认语义：滑块不丢默认基准，`buildReadingCSS` 以根锚缩放。

#### 背景色：深浅成对 + 独立覆盖

- 日夜切换 = **整套配色**（前景文字色 ⇄ 背景色 ⇄ 强调色 ⇄ 容器阴影）成对定义，`SCHEMES`(day/night) 定义「背景 + 正文字色」成套，`buildReadingCSS` 同时注入 `html`/`body` 的 `background+color`（根治「只切背景不切文字 → 夜黑字黑」）。
- 允许用户**单独覆盖背景色**这一项（`bgOverride`，hex，空=跟随时），再一键在两个整套配色间切换。
- 暗色背景主题只经夜间按钮整套切换，**不作为单独背景色选项**。

## 7. 科技渲染（外置预处理 + 干净 HTML 喂给 foliate）

> 核心原则：**LaTeX / ABC 乐谱 / Mermaid 等局部重计算元素，不在 WebView 主线程做**。外置独立 JS 运行时（QuickJS）预处理，输出 SVG 片段，再交给 foliate。

**数据流完整链路**

```
EPUB 原始 XHTML 片段（Kotlin 读出）
        ↓
【外置预处理层：QuickJS】
  ├─ 匹配 $...$ / $$...$$ / ```abc / ```mermaid 标记
  ├─ 调用 katex.renderToString() / ABCJS.renderAbc() / mermaid.render()
  └─ 输出 SVG 字符串，原地替换标记块
        ↓
产出：已经完全替换为 SVG 的干净 XHTML
        ↓
送入 WebView → foliate-js（DOM 挂载、CSS 排版、分页、CFI 映射、交互）
```

**关键点**
1. QuickJS 无 DOM、无 window，只跑纯函数，做「字符串 → SVG 字符串」转换；
2. foliate 拿到的已是普通 SVG 标签，与普通图片无差别，`transformTarget` 不做重型渲染；
3. WebView 主线程不再承担 LaTeX/乐谱语法解析的 CPU 开销，只做布局绘制。

**边界处理**
1. Prism 代码高亮统一挪入 QuickJS，输出带样式的 `<pre><code>`。
2. 原书自带 MathML 直接放行，交给 WebView 原生 MathML 渲染；QuickJS 只处理 LaTeX 源码/abc/mermaid 代码块。
3. 防断裂 CSS 随字体/排版层注入。

### 7.1 CFI 映射完整性（本方案最大坑）
预处理会改 DOM，破坏原书 CFI。故：**CFI 以原始未处理 XHTML 为基准**；预处理只做视觉替换，同时在 Kotlin 层维护「原始位置 ↔ 替换后 DOM」映射表。foliate 上报选区/CFI 时反向映射回原始文档 CFI，书签/笔记才不会错位。

### 7.2 技术选型（Android）
- JS 运行时：**QuickJS-Android**（so 库约 600–800KB，无浏览器 API，纯函数执行）；打包进 katex（仅 renderToString）/abcjs（渲染函数）/mermaid（headless SVG）。
- 输入输出全部字符串，不跨边界传 DOM 对象。mermaid 用 `render()` 无 DOM 回调接口。

### 7.3 两套预案
1. **主路径**：Kotlin 侧 QuickJS 预处理，送入 foliate 干净 HTML。
2. **降级预案**：退回 WebView 内 **Web Worker** 执行同样转换，不占主线程。

## 8. 分页模型重构：屏级小节 + 字符偏移锚点（针对大章节卡顿）

> 状态：**方案已确定，待落地**。背景为 GIMP 3.0 用户手册这类「章节长、样式复杂」的书籍在大章节里各种操作都卡（打开、翻到、翻页、改设置重排全面卡顿）。

### 8.1 问题根源

现状以「章」为排版单位，衍生两大硬伤：

| 痛点 | 根因 |
|---|---|
| 大章节各种操作全卡 | 整章一次铺进 DOM / 一次排版。结构树、scrollWidth、layout 树全部按**整章内容量**实体存在，一次布局的 CPU 与内存都随章长增长，与视口外是否绘制无关 |
| 改字号/行距/旋转屏基点跑掉 | 改设置 = 整章从头重排 + 用**像素 page index** 找「当时第几页」定位。像素一变就漂移，用户盯着的那段文字被拉到前面/顶到后面 |

### 8.2 结论与原则

- **「只渲染少量页」是唯一根治路径**（大章节内存/CPU 必须与章长解耦）。
- **不自写分页内核**。LaTeX/MathML/SVG/表格是「原子块」，跨页断行、字形级 CJK 禁则依赖浏览器 CSS fragmentation 几十年打磨；自写内核极易在跨页处切断，且 CFI→(页,位置) 需整套重写、定位漂移。风险远大于收益。
- **关键事实**：CSS 多栏是一文档一次碎片化，**做不到「只排一部分列」**。foliate 的 `expand()` 一次性量出整章所有页。因此「只渲染周围几页」**不能靠拖现有 columns 实现**，必须把大章拆成多个独立小节，让 foliate 的三窗口机制只看到一小段。

### 8.3 改造架构

```
大章节 ──当前阅读位置懒拆──▶ 切成 N 个「段落段」(每段≈3~8屏)
                                          │  每段 = 一个小节 section(复用 spine index+anchor 机制)
                                          ▼
             foliate 三窗口(前/中/后) 只渲染 3 节 ──▶ 其余节不渲染(内存/CPU 与章长无关)
```

1. **切分以「块」为粒度、段≈3~8屏**(10 屏为不卡上限)，切成若干独立小节，塞入 `book.sections`（复用 foliate 的 index+anchor 机制）。foliate 现成的 `#shiftWindow` 自动只保留 3 节 → 正好实现「只渲染周围少数页」。
2. **每小节排版仍交给浏览器多栏**（每节 DOM 小，columnize 快）→ 不自写内核，MathML/SVG/表格断行、CJK 禁则全由浏览器保证。
3. **切分按块懒执行**：不做「离屏预排整章量断点」（WebView 无真后台 DOM 排版，伪后台仍在主线程、卡白屏只变延迟）。改为：随当前阅读位置**懒拆当前章**，其他章按需拆；拆分当前章时先渲染首段再拆其余，避免阻塞首屏。
4. **重排基点稳定 → 字符偏移锚点**：改字号/行距/旋转屏只需重排当前±1 节（后台异步），并用「原始章节序号 + 第 N 个字符」锚回同一段文字 → 用户边调边盯的基点不掉。
5. **定位持久化 = 字符偏移**：书签/进度记「原章节序号 + 字符偏移」，重切后按偏移找回，而非像素 page index。

### 8.4 落地效果与代价

| 项 | 效果 |
|---|---|
| 内存 / 单次布局 CPU | 与章长无关注（只渲染 3 节） |
| 大章节打开 / 翻页 / 改设置 | 翻页全程顺滑，无一次性全量排版 |
| 改字号/行距/旋转屏 | 基点稳定，边调边看不跑位 |
| MathML/SVG/LaTeX/表格 兼容 | 保留（浏览器多栏断行） |
| 标注/CFI 定位 | 用字符偏移持久化，重切可靠找回 |

**真实代价**：改字号/行距/旋转屏 = 屏级切分会失效 → 需后台重切全部小节 + 按字符偏移还原位置。缓解：重切放后台、只重排当前±1 节、用字符偏移保位置。用户读大章全程顺滑，仅改设置那一次短暂后台重切。

### 8.5 落地闭环（第一版最小范围）

1. 按当前阅读位置把大章**懒拆**成若干「段落段」（每段≈3~8 屏、块边界切分 + 全链路容器克隆），塞入 `book.sections`。
2. foliate 现成 `#shiftWindow` 自动只渲染 3 节 → 内存/CPU 与章长无关。
3. 每小节走浏览器多栏排版 → MathML/SVG/表格断行、CJK 禁则保留。
4. 书签/进度/基点位置用**字符偏移**持久化，重排后锚回。
5. 第一版只理顺「切分 + 顺滑翻页 + 不卡 + 基点稳定」；标注的完整 CFI 重映射放第二步验证。

## 9. 决策录（含已拍板项）

**已对齐确认**
- 科技渲染：外置 QuickJS 预处理 → 干净 HTML 喂 foliate（§7）。
- 卷页动画：先滑动稳定、再卷页。
- **分页模型**：大章节拆成「屏级小节」，只渲染少量页；进度/书签/基点用**字符偏移锚点**持久化（§8）。
- 位图 pager：位图管线作为卷页与动画的地基。
- 定位：CFI 以原始 XHTML 为基准 + 位置映射表，随「外置 QuickJS 预处理」落实。
- 渲染只交给 foliate-js；解析/定位/持久化/动画/字体分层全在 Kotlin。
- ES Module / fetch 跨域问题 → 用 `WebViewAssetLoader` 走 https 虚拟域，不用 `file://`。
- 书源存**应用私有目录副本**（导入即拷进 `filesDir/books/`），不长期依赖 SAF content://（重启后授权不可靠）。

**剩余决策点（不阻塞当前进度）**
- **文本交互 vs 动画取舍**：后续走「位图 pager（滑流畅、文本交互有限）」，做卷页动画时再评估是否引入每页独立 WebView 的增强文本交互路径。
